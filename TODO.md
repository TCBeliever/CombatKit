## Extras: announce my focus marker (Mythic+)

Say once in party chat which raid marker my focus-kick macro uses, e.g. `My focus marker is {rt3}`, so the group can avoid using the same one.

Researched 2026-09-21, nothing built, nothing tested in game.

- **How others do it.** Mythic Dungeon Tools (its FocusMarker module, `Modules/FocusMarker.lua`, option "Announce my Focus Marker on ready check") and Stormseer's FocusMarker (GitHub) both announce on `READY_CHECK` with `C_ChatInfo.SendChatMessage(text, "PARTY")`. The marker is a user setting; nobody parses the player's macros. `{rt1}`..`{rt8}` works in every client language.
- **What 12.x forbids.** From the moment a keystone is inserted until the run is over, during encounters and during PvP matches, addons cannot send chat (`C_ChatInfo.InChatMessagingLockdown()`, restriction type `Enum.AddOnRestrictionType.Chat`). So "when the countdown starts" and "right after the key starts" are not possible. On zoning in is possible but early: the group may not be there yet, and it also fires in a Mythic dungeon without a key.
- **Plan.** A third feature in the Misc module ("Extras"), about 50 lines:
  - settings: the marker (1-8), the sentence;
  - trigger: `READY_CHECK`, in a party (not a raid), not in combat, not in chat lockdown (check the API exists; `pcall` the send);
  - once per group and instance: remember instance id + the sorted party GUIDs, announce again only when that changes;
  - reference guards in other addons: ClassReminders' `BuffRequests.lua` (lockdown check with fallback), Leatrix Plus ("Chat messages are restricted right now").
- **Open questions for the user.** Ready check only, or also "on entering the dungeon" as a second option? Default sentence in Chinese, English, or both?
- **To verify in game.** When exactly the chat restriction switches on relative to the keystone countdown, and whether a blocked send raises an error or fails silently. The CVars `addonChatRestrictionsForced` / `addonChallengeModeRestrictionsForced` simulate the restricted state.

## Reminders: a module that says what is missing before a pull

Researched 2026-10-09 from ClassReminders 3.0.6 (67k lines, six libraries; the sibling addons Castbar, Resources, Pets, CooldownManager, ExternalBuffs were not read). Nothing built.

- **What it reminds about.** Group buffs: Battle Shout 6673, Arcane Intellect 1459, Power Word: Fortitude 21562, Mark of the Wild 1126, Blessing of Bronze 364342 (buff IDs 381732-381758), Skyfury 462854/204330; shown when any eligible group member lacks it (solo: yourself). Self buffs and forms: Devotion Aura 465, Arcane Familiar 210126, shaman shields 974/383648, 192106, 52127 (two with Elemental Orbit 383010), shaman imbues (enchant 5401 Windfury, 5400 Flametongue, 6498 Earthliving), paladin rites 433583/7144 and 433568/7143, rogue poisons (lethal 315584, 8679, 2823, 381664; non-lethal 3408, 381637, 5761; two of each with Dragon-Tempered Blades 381801), DK runeforges by spec and talent (enchant 3368 Fallen Crusader, 3370 Razorice, 3847 Stoneskin, 6241 Sanguination, 6245 Apocalypse), Grimoire of Sacrifice buff 196099, Healthstone items 5512/224464, Shadowform and Moonkin via `GetShapeshiftForm`, Defensive Stance 386208 as a warning to leave it. Consumables: augment rune auras {1264426, 1234969, 1242347, 453250}, flask auras {1235057, 1235108, 1235110, 1235111, 432021, 431971-431974}, food = any buff with icon 136000, weapon oil via `GetWeaponEnchantInfo()`. Gear: durability under 30%, equipment set for the spec not equipped, preferred trinkets per spec. Custom auras: any spell ID, buff/debuff, player/group, present/missing.
- **When.** Everything with auras is out of combat only; also hidden while dead, in a key, in an encounter, in a vehicle, for 12 s after a loading screen, in a rest area, in PvP, and (default) outside dungeons and raids. Consumables additionally stop after the first pull of the visit, or show only during a ready check. "Expiring in N minutes" is read out of combat only. A dungeon is `IsInInstance()` party/raid/scenario **and** `difficultyID > 0`: grouped players in the 12.x hub cities report "party".
- **How it reads auras under 12.x.** `C_UnitAuras.GetPlayerAuraBySpellID` with fixed IDs; the `UNIT_AURA` payload is never looked at (it can be secret), the event is player-only via `RegisterUnitEvent` and just triggers a rescan of the fixed ID set against a cache. Every read: `pcall`, then `issecretvalue`, `canaccessvalue`, `canaccesstable`; a result it cannot read is "unknown", and unknown is never shown as missing. `C_Secrets.ShouldAurasBeSecret()` is the authoritative predicate. Indexed scans (`GetBuffDataByIndex`, the food check) are the fragile ones. Group buffs are polled with a 1.5 s ticker only while grouped, out of combat.
- **How it shows.** One icon with a text above it per reminder, glow, bounce, a sound when it appears, click-to-cast through a secure overlay hidden in combat by a state driver, an optional grid that packs them. Per-reminder position, font, glow, sound, instance filters: most of the 67k lines are that.
- **How it places them.** Every reminder is its own frame at an x/y offset from the screen centre (default above the character), or anchored to a frame the player names; dragging while unlocked saves the spot. An opt-in "Autogrow" container packs the ticked reminders into one centred row or column (grid with wrap, spacing, max per line), shared by all characters; inside it the label moves into the icon. The options sort reminders by class (one entry for your class with feature tabs: Warrior "Stances / Buffs", Shaman "Buffs / Shields / Weapon Imbues", Warlock "Pet / Healthstone / Soulstone / Burning Rush / Grimoires", Rogue "Poisons", DK "Runeforging / Pets", ...) and a general group: Consumables, Trinkets, Gear Sets, Gear Repair, Feast Alert, External Buffs, Gateway.
- **Decisions (2026-10-09).** The module is called *Reminder* in every language: the Chinese "提醒" reads badly, so the name is not translated. Keep its icon experience: one icon per reminder, the text above it, the size and the spell/item icon as ClassReminders shows them. One container that packs the active icons in a row is the default placement, not a position per reminder.
- **Plan for the kit.** A fifth module, "Reminder": icons on screen as above, packed in one row that the player drags; optionally the same items as rows on the HUD. No click-to-cast (needs a secure overlay; later, if at all); no sounds at first. Scope for the first cut: the consumables, the self-buff subset above for the player's class, and the player's own group buff. Gate as ClassReminders does, with the kit's scenario (dungeon, raid) instead of `IsInInstance` and the loadout's "until the first combat of the visit" rule. Skip pets, Soulstone, feasts, trinkets and gear sets (the loadout covers gear). Custom spell IDs later. Settings grouped by what triggers them, not by class: the player only ever sees their own class anyway.
- **Per-class code.** One Lua file per class in the module, each registering a factory `ns.classes.<TOKEN> = function(L) return {...} end`. On enable the module calls its own class's factory and sets `ns.classes = nil`, so the other classes' closures and their bytecode are collected: only the player's class stays in memory. Not one addon per class: the game loads on demand by addon only, that would be 13 more folders in the AddOns list for a few dozen KB.
- **Import and export (added 2026-10-09).** A settings string to copy out of and paste into the kit, for the Reminder module and, since it costs the same, the whole kit: one page under Settings with a text box, *Export* and *Import*. ClassReminders does it with AceSerializer + LibDeflate + `EncodeForPrint`; the kit carries no libraries, so its own serializer (tables of strings, numbers, booleans; a version field; a prefix that names what the string holds) and a printable encoding, about a hundred lines. Per-character data (the loadouts) travel by name, so a string from another character applies only where the same loadouts and sets exist; say so on import.
- **To verify in game.** `C_Secrets.ShouldAurasBeSecret` exists on 12.1; `GetWeaponEnchantInfo()` enchant IDs are readable out of combat; the food icon 136000 still holds for Midnight food.
