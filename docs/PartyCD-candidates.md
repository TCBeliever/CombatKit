# Party CD: candidates from the game's data

> Generated by `tools/candidates.py` from the game's data files (DB2, via wago.tools), build 12.1.5.70391, on 2026-10-14.
> Do not edit: change `tools/candidates_decisions.tsv` (the decisions) and run `python tools/candidates.py` again.

Every ability below comes from the game's own tables only: the class skill line, the live talent trees,
the specializations' spells and the PvP talents (the universe), kept when it is active, has a cooldown of
20 s or more and leaves an aura the module can see on the caster, an ally or an opponent (the cast's own
apply-aura effects, or those of a spell it triggers, one link down; when the data links the cast to no aura,
the aura spells of the same name in the class's spell family). A talent's or PvP talent's spell on the same
button is listed under the base ability (`casts`). The decision and its reason are written by hand.
Racial abilities come from each race's own skill line ("Racial - Dwarf"), for the races its race mask
names, and are listed last under *Racial*, the races in place of the specializations.

Universe: 4596 spells. Candidates: 406 (in 185, out 221, undecided 0).

Columns: *Auras* lists each aura ID and where it lands (caster, ally, allies, enemy, enemies): `<- X` when
cast X triggers it, `[X]` when X (a version on the same button) applies it, `by name of X` when nothing in
the data links X to an aura and the aura is the spell of the same name the server applies (Storm Bolt's
stun); then what the aura does, where the data says so. *Seen* is the constructor the data points at.
*Listed* says whether Spells.lua has it: as an entry (with its constructor when that differs from *Seen*),
or under one as a cast or an aura.
